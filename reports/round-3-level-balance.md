# 第三轮：关卡平衡、通关验证与三星评价 · 报告

> 结论先行：**10 关全部真实可通（一发射击即可通关），但实测发现 3 个关卡存在"不合理难度"**——
> 1-2（屋顶鸟巢）4.1%→9.4%、1-6（玻璃塔）1.0%→2.6%、1-10（堡垒）反而过易 33.5%→18.7%。
> 三处改动**只动 `src/game/levels.ts` 的关卡数据**，未改物理、未改评分规则、未改弹射手感。
> 另外补了"失败原因"反馈（引擎采集客观事实 → 纯函数措辞），修掉了结算面板只能显示一句通用文案的问题。

## A. 项目审查

### A.1 评分系统的唯一规则源（代码核实，不采信注释）

| 项目 | 实现位置 | 核实结果 |
| --- | --- | --- |
| 三星判定 | `src/game/rating.ts` `rateStars()` | 三颗星 = 三个独立目标：①抢到鸟蛋（恒真）②`usedPigs ≤ STAR_PIG_LIMIT(2)` ③破坏表现 = `maxChain ≥ 3` **或** `birdsCaptured ≥ 1` **或** `breakScore ≥ levelWorth × 0.4` |
| 总分 | `rating.ts` `totalScore()` | `breakScore + chainBonus + birdScore + pigBonus + eggBonus` 五项一次求和；`engine.win()` 与 `drainBreaks()` 都调它，不存在两处各算一遍 |
| 破坏分 | `engine.drainBreaks()` | 每块只结算一次（`blockMeta.delete` 后不可再入队），不重复计分 |
| 连锁分 | `engine.drainBreaks()` | 第 3 块起 `(chain-2)×10`，只在同一 `CHAIN_WINDOW_MS` 窗口内累加，不清零重复 |
| 撞鸟分 | `engine.captureBird()` | `bird.captured` 守卫 → 同一只鸟只能 +150 一次；通关后（`pendingWin`）撞鸟只播表现不计分 → HUD 与结算不会跳分 |
| 剩余猪奖励 | `engine.win()` | `pigBonus = 剩余猪 × 200`，一次计算 |
| 蛋奖励 | `engine.win()` | `EGG_BONUS = 1000`，`win()` 只可能进一次 (`state` 守卫) |
| 破坏阈值分母 | `engine.buildWorld()` | `levelWorth` = 本关所有方块 `MATERIALS[mat].score` 之和（改方块会自动跟着变，无硬编码） |

**结论：不存在刷分、重复计数、面板与存档不一致的问题。** 唯一的"评分设计争议"是第③颗星在"干净命中"型关卡里要求拆迁，见 D 段。

### A.3 发现的问题清单（按严重度）

- **P1（严重）1-2 的鸟蛋实际不可达**：蛋是**静态刚体**（`engine.ts` `Bodies.circle(..., { isStatic: true })`），而巢的底板是 44 厚木台（`wood hp=8`，猪正面撞的 `harm` 远超 1）。任何正中命中都会先把木台打碎，蛋留在半空、离地 190px，猪落地后与蛋的最近距离一直是 69px（判定需 ≤ 48px）→ 只有"恰好从空中穿过蛋"这一种极端弧线能赢，实测 4.1%。
- **P2（严重）1-6 的红鸟违反项目自己的摆放铁律**：红鸟 `(1250, 560)`，而台面顶面 y=606 → 鸟底 586，**悬空 20px**；且正好停在巢口左翼的进场通道上，任何从左往右的低平弹道都会先撞鸟被弹回。实测 1.0%。
- **P3（明显）1-10 难度倒挂**：33.5% 通关（除教学关外全场第一），因为外墙内侧一片空场、蛋就摆在门厅地面，平射即可；同时蓝鸟 `cy=240` 的巡逻椭圆完全在屋顶之上，对任何弹道都没有威胁 → 末关既不难也没用上全部机关。
- **P4（一般）三星在"干净命中"关卡偏难**：1-2 / 1-4 / 1-9 的三星点大部分要"两发 + 技能"才能满足 40% 拆迁，因为一发射进巢几乎不拆东西（1-9 稳定三星 0.9%，全场最低）。
- **P5（一般）1-6 / 1-8 处于"针尖上"**：稳定通关 0.6% / 2.1%，且 1-6 的解大多依赖 TNT 连锁时序（种子敏感）。1-8 属于设计意图（信箱口），1-6 已修到 2.3%。
- **P6（轻微）失败面板没有原因**：只显示"{N} 只小猪都用完了"和一句通用建议，玩家不知道是"射程过头"还是"被挡"。
- **P7（轻微）结算面板没写三星达标线**：只显示"连锁 ×2 · 撞鸟 0 · 拆迁 24%"，玩家不知道要多少才够。
- **P8（信息）开局沉降**：1-5/1-8/1-10 开局 2.4s 内上层结构整体下沉 5~9px（Matter 接触 slop 累积），一次到底、不再抖动、得分保持 0 → 属正常解算，非"自毁"。
- **P9（信息）`spy`（间谍猪）全场最弱**：免疫 2000ms 只对撞鸟有效，而撞鸟本来只是加分项，且钢盔猪是"免费免疫 + 不减速"。实测各关首发占比 `spy` 从未超过同关其它猪（见 E）。

## C. 通关测试（覆盖范围、次数、结果）

### C.1 测试机制（与游戏代码隔离）

- 测试工具全部位于 `scripts/balance/`（`entry.ts` + `harness.mjs` + 12 个 CLI 脚本），**用 esbuild 把真实的 `src/game/*` 打包成 CJS 后驱动真实 `GameEngine`**，不写第二套物理。
- 浏览器 API 用替身补齐（canvas / Image / fetch / localStorage / window / rAF），`eng.render = noop`，所以只跑逻辑不跑画面。
- **不写玩家 localStorage**（替身是内存对象）、**不走 `applyWin` 存档/成就**、**不改正式关卡数据**（对照实验用 `structuredClone(LEVELS)` 的内存克隆）、**没有测试按钮**、**引擎未做任何测试专用改造**。
- 发射方式与真实玩家完全一致：设 `eng.dragPos` 后调 `eng.onPointerUp()`；技能用 `skillAtStep` 在飞行中触发。
- 随机性：所有测试固定 `Math.random` 种子（mulberry32），每个参数点跑 3 个种子，只有 3 个种子都通关才算"稳定"。
- 覆盖范围：角度 4°~72°（步长 4°）、力度 78~150（步长 4，即玩家满拉区的 80%~100%）、全部猪种各作为首发/第二发/第三发、主动技能猪额外覆盖"技能在第 20/32 步触发"。**以下是"当前测试范围内"的结论，不代表全局最优。**

## D. 三星可达性

规则（代码核实）：一星=抢到蛋；二星=`usedPigs ≤ 2`；三星=二星 + 破坏表现（连锁 ×3 / 撞鸟 1 只 / 拆迁 40%）。

| 关 | 稳定 3★ | 稳定 2★ | 首发即可 3★ | 三星实际依赖 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 1-1 | 6.8% | 35.8% | 26 点 | 一发进蛋 + 玻璃柱/木顶被顺带打碎 | 合理 |
| 1-2 | 1.8% | 6.7% | 7 点 | 需顺带撞飞红鸟或拆石台 | 偏难（见 G-3） |
| 1-3 | 10.1% | 5.2% | 79 点 | TNT 连锁自然满足 | 合理 |
| 1-4 | 1.5% | 7.9% | 8 点 | 主要靠"教授猪点爆 TNT" | 偏难但路径明确 |
| 1-5 | 10.2% | 2.0% | 41 点 | 两发拆塔自然满足 | 合理 |
| 1-6 | 0.8% | 1.6% | 1 点 | 一击穿塔时顺带拆玻璃 | 偏难（同 G-2） |
| 1-7 | 7.1% | 7.9% | 38 点 | 翻墙时砸到主屋 / 撞鸟 | 合理 |
| 1-8 | 1.9% | 0.3% | 21 点 | 点炸 TNT 连锁（几乎必然触发） | 合理（难在通关本身，不在三星） |
| 1-9 | 0.9% | 13.0% | 3 点（均带技能） | 必须两发 + 厨师/教授技能才够 40% 拆迁 | **偏难（最低）** |
| 1-10 | 12.8% | 0% | 54 点 | 炸外墙的连锁自然满足 | 合理（三星≈通关，见 G-5） |

**关键观察**

1. **不存在刷分路径**：撞鸟只能一次、方块只能结算一次、蛋奖励一次，三星全是"事实"而非"操作次数"。
2. **1-10 的三星 = 通关**（12.8% vs 12.8%），因为它的 `levelWorth` 很大且必炸 TNT → 拆迁 40% 几乎自动达成。这不影响公平性，但意味着末关的第三颗星没有区分度。
3. **1-9 的问题是"干净打法拿不到三星"**：钻矮缝几乎不拆东西，三星只留给"两发+技能"这条高难路线（0.9%，其中首发 3★ 仅 3 个点且都要求技能）。这里没有下调阈值，原因见 G-1。

| helmet 钢盔猪 | 被动：撞鸟不减速、不反弹 | **1-3 32.2%（vs 18.9）/ 1-4 24.4%（vs 8.9~10）**；1-2 反而最低（5.6%，质量大弧线沉） | 鸟关的"对策猪"，明显优于其它选择——**但这是设计意图（反鸟）**，且只在有拦截的情况下强 |
| prof 教授猪 | 主动：空中引爆（185px） | 1-10 技能 10%→23.3%（+13.3）；1-4 首发 8.9% 主要靠它点爆 TNT；1-2/1-7/1-8 技能几乎无收益（+0~1.1） | 强依赖关卡是否有"值得炸的目标"，在纯投送关无用 |
| chef 厨师猪 | 主动：速度 ×1.9 + 5（可撞穿木/玻璃） | **1-5 14.4→26.7（+12.3）、1-6 1.1→8.9（+7.8）、1-9 15.6→27.8（+12.2）、1-10 12.2→23.3（+11.1）**；1-3 反而 -3.3（加速过头） | **全场最有价值的技能**（穿墙/钻缝/补射程），且并非万能（会过头） |
| king 国王猪 | 被动：质量 3.6 | 1-10 21.1%（最高）；1-5 15.6%（最高） | 硬砸型解，与 chef 技能形成"稳 vs 强"的分工，健康 |
| spy 间谍猪 | 主动：免疫 2000ms | 1-4 10%（helmet 24.4%）、1-5 14.4%（king 15.6%）、1-9 13.3%（chef 15.6%）；技能收益 +1.1 以内 | **最弱的一只**：免疫只在撞鸟时有意义，而钢盔猪免费做到且不减速 → 同关几乎总有更好的选择 |

**"是否有支配猪 / 废物猪"**：`helmet` 在 1-3、1-4 支配；`king` 在 1-10 支配；`chef` 的技能在 5 关里都是"最强补强"。`spy` 没有一关能胜出（见 G-6）。这只猪的问题在**技能设计**而非关卡数值，本轮不动它（本轮限定不改猪/技能）。

## F. 修改记录

> 全部改动**只涉及关卡数据 + 文案/反馈**，未改 `engine.ts` 物理与判定、未改 `rating.ts` 阈值、未改弹射操作、未改材质体系。
> 每项均给出"改前实测 → 改后实测"，且都重跑了全关撒点确认不波及其它关。

### F-1 1-2 屋顶鸟巢：巢整体下移 60px + 台面改石（P1）

- 原问题：蛋（静态刚体）架在 44 厚**木台面**上，木 `hp=8`，猪一发正中必定打碎台面 → 蛋悬空 44px，猪落地后与蛋最近 69px（判定需 ≤48px）→ 只有"空中恰好穿过蛋"能赢，实测能通 4.1%、稳定 4.1%。
- 判定为问题的依据：实验室对照（20 余个变体）中，把台面换成 stone（`hp=22`，是 wood 的近 3 倍）后能通翻倍，且**开局沉降仍为 1.6px、开局 6s 得分 0**。
- 改动（`levels.ts` 1-2）：
  - 冰玻璃柱 `150` 高 → `90` 高（y 725 → 755，仍压在地面 800 上）；
  - 台面 `wood(1340,628,260,44)` → `stone(1340,688,260,44)`（顶面 666）；
  - 石柱 `stone(1244,566,44,80)` → `stone(1244,626,44,80)`（坐在台面顶 666 上，面贴面）；
  - 蛋 `y 582 → 642`（坐台面顶 666）；台面上的红鸟 `y 580 → 640`（踩台面顶，符合"站桩红鸟必须踩在方块顶面"）；
  - hint 改为"蛋搬到石台上了。冰玻璃柱一撞就碎，石台硬得多——把猪抛上屋顶，让它滚进巢里，别正面硬砸台面。"（**不能写成"石台砸不烂"**：stone `hp=22`，满力正面命中 `harm = 33×1/22 ≈ 1.5` 仍会碎，只是斜落/滚行不会再顺手打塌它）。
- 实测：能通 4.1% → **9.4%**，稳定 4.1% → **8.4%**，稳定三星 1.2% → **1.8%**。
- 副作用检查：其它 9 关数据未变，撒点结果逐位一致。

### F-2 1-6 玻璃塔：把堵门的红鸟挪到台面右端（P2）

- 原问题：红鸟 `(1250,560)`——①悬空 20px（台面顶 606，鸟底 586），违反摆放铁律；②它正好停在巢口左翼的进场通道上，任何低平弹道都先撞鸟，1.0% 能通、0.6% 稳定。
- 排除的替代方案（实测均无改善或无意义）：蛋左移 20/32/38、巢下移 60/100/120、台面加宽 340/360、冰砖右移、镜头右侧加砖——能通全部停在 1~3.5%；而"移走红鸟"直接从 1.2%（2 种子）→ 2.6%。
- 改动：`{ kind:'red', x:1250, y:560 }` → `{ kind:'red', x:1480, y:580 }`（踩台面顶 606，位于台面右端，不再挡巢口）。
- 实测：能通 1.0% → **2.6%**，稳定 0.6% → **2.3%**，稳定三星 0.4% → **0.8%**；并首次出现"首发即三星"的解（`52°/150`）。
- 副作用检查：开局沉降 1.5px、得分 0；蓝鸟轨道（1070~1290）与新鸟位（1454~1506）无重叠。

### F-3 1-10 鸟巢堡垒：门口加一道石障 + 蓝鸟巡逻压低（P3）

- 原问题：33.5% 能通 / 28.7% 稳定，是除教学关外最好打的关；蓝鸟 `cy=240, ry=55` 的椭圆完全在屋顶之上，对任何弹道都没有威胁（等于一只"摆设鸟"）。
- 改动：
  - `blocks` 追加 `stone(1300, 750, 44, 100)`（门厅矮石障，700~800，不与一层顶 640 接触，纯路障）；
  - 蓝鸟 `cy 240 → 500`、`ry 55 → 46`（新椭圆 y 454~546，x 930~1150，与外墙 AABB 1118~1162 **不重叠**，留 2px 以上间隙）；
  - hint 补上"门口石障"。
- 实测：能通 33.5% → **18.7%**，稳定 28.7% → **12.8%**，稳定三星 18.5% → **12.8%**。
- 备选方案与取舍：门柱做到贴一层顶（承重柱，800~640）实测 15.4%/11.8%，但会改变整栋楼的受力与塌法；矮石障实测 16.5%/12.0%（步长 6）与承重柱等效，却不动主结构，故选矮石障。
- 副作用检查：开局沉降仍是既有的 5.6px（与改前完全一致，未新增抖动），开局得分 0；TNT 连锁、蛋位、猪队均未变。

### F-4 失败原因反馈（P6，`engine.ts` + `feedback.ts` + 双端 UI）

- 引擎只新增**采集**：`shotClosest`（最后一发离蛋最近距离）、`shotContacts`（撞到场景物件次数）、`shotFar`（最后一发到达过的最右 x）、`tntLeft`、`springLeft`，通过 `onLose(info)` 传出，**不参与任何判定**（`LoseInfo` 在 `types.ts`）。
- 新增 `src/game/feedback.ts`（纯函数 `describeLose`），按事实分三类措辞：
  1. 什么都没碰到 → 用 `shotFar` 与蛋的 x 比较，区分"没飞到就落地"（建议加力度/抬角度）与"越过飞过去了"（建议收力度/压角度），并给出具体数字（`最远到 x=268，鸟蛋在 x=1370`）；
  2. 撞到东西且离蛋 ≤90px → "只差 xx px"；
  3. 撞在建筑上、离蛋仍远 → "最近只到 xx px"，并从关卡数据里取一条可执行建议（还剩 N 个炸药箱没点着 / 弹簧板一次没踩到 / 换个角度先打支柱）。
- 实测验证：两版都用"连打三发弱射"的脚本跑到真实失败面板，React 显示`最后一发没飞到鸟蛋就落地了（最远到 x=268，鸟蛋在 x=1370）。/ 加 30 点力度，或者把角度再抬 1~2 度。`，standalone（`file://`）文案逐字一致。
- React（`GameShell.tsx`）与 standalone（`main.ts`）**共用同一个函数**，两版文案一致。
- 不再使用"你没有通关"这类空话，也不含羞辱性表达。

## G. 尚未解决的问题与建议

1. **G-1（不修，仅记录）1-9 三星率 0.9%（全场最低）**。钻矮缝几乎不拆东西，三星只留给"两发 + 技能"路线。**没有下调该关三星阈值**，理由：一星/二星很容易（稳定通关 13.9%），玩家不会卡关；而 40% 拆迁是全局唯一阈值，为单关加"每关独立阈值"要新增一条配置通道与提示文案，收益（0.9%→约 2%）不抵复杂度。若后续确有玩家反馈，最小改法是给 `LevelDef` 加 `starDemolishRatio?: number`，只对 1-9 取 0.3。
2. **G-2（不修，仅记录）1-8 稳定通关 2.1%**。它是"信箱口"关（蛋在 120px 高的信箱口里，必须先炸断塔腿），属于明确的技巧关，且三星率/通关率 = 90%（说明它难在通关而非三星）。1-6 修完后与它形成"垂直投送 / 水平塞入"两档，保留。
3. **G-3（观察）1-2 稳定三星仅 1.8%**。原因是一发进巢几乎不拆东西，第三颗星要靠"顺带撞飞红鸟"或"拆掉石台"。若后续觉得太苛，建议把台面上的红鸟往弹道落点方向再挪 20~30px（会同时提高撞鸟概率），而不是降阈值。
4. **G-4（既有现象，非本轮引入）开局沉降 5~9px**：1-5 上层 8.9px、1-8 5.7px、1-10 5.6px，2.4s 内一次到位、之后不再抖动、得分恒为 0。来自 Matter 接触 slop 沿多层叠放的累积。彻底消除需要给方块预留 1px 缝隙或调 `slop`，会改变破坏手感，本轮不动。
5. **G-5（观察）1-10 三星 ≈ 通关**（12.8% vs 12.8%）：末关 levelWorth 大、必炸 TNT，第三颗星自动满足。不影响公平，但末关三星没有区分度。若要区分，只能改关卡结构（例如去掉必炸的连锁），代价大于收益。
6. **G-6（本轮不改）`spy` 间谍猪价值最低**：免疫 2000ms 只在撞鸟时有意义，而钢盔猪免费免疫且不减速。本轮限定"不新增/不改猪"，建议后续把 `spy` 的免疫扩展为"免疫击退 + 穿透一层玻璃/木"，或给一个"受击后获得一次短冲"的主动效果，让它有独立战术位。
7. **G-7（既有）静态鸟蛋 + 可破坏台面是系统性隐患**：任何"巢底板可被打碎"的关卡，蛋都可能悬空而变得实际不可达（1-2 就是这么来的）。本轮用"台面换石头 / 挪开挡门鸟"绕开，没有改引擎。**根治方案**是让蛋跟随支撑体下落（改成动态刚体 + `inertia: Infinity`），涉及判定点、绘制坐标、瞄准预测三处，风险高于收益，列为后续专项。
8. **G-8（测量局限）**：所有占比都是"均匀撒点"下的相对难度，玩家实际有弹道预测辅助（分段轨迹 + 蛋的可达性提示），体感会比数字宽松；4° 角度步长 / 4 力度步长之外的极窄解可能未被采样到（因此统一表述为"当前测试范围内"）。
